# Telegram Stars Worker

Платёжный сервис для Telegram-сборки игры «Алик, Где Деньги?». Принимает Stars за товар
«Чашка хаша для Алика», ведёт журнал платежей в Cloudflare D1 и умеет возвращать Stars
через тот же workflow, которым устанавливается.

Подпроект изолирован: собственные `package.json`, lockfile, конфигурация Wrangler, миграции
и тесты. Браузерная сборка игры, корневые npm-скрипты и существующие workflow не меняются.

- Free-тариф: Cloudflare Workers Free + D1 Free (без платных продуктов).
- Игра остаётся на GitHub Pages, бот — `@alik_where_money_bot`.
- Установка для оператора — один запуск workflow **Telegram Stars Worker**, режим `deploy`.

## Границы доверия

| Что | Кому доверяем | Почему |
|---|---|---|
| Цена, валюта, товар | строке каталога в D1 | её пишет установщик; браузер и инвойс цену не задают |
| Факт оплаты | `message.successful_payment` от Telegram | подпись-заголовок `X-Telegram-Bot-Api-Secret-Token` знает только Telegram и Worker |
| Возврат | ручному workflow `refund` | charge ID и user ID берутся из журнала, а не из HTTP-запроса |
| `paid` в клиенте (`WebApp.openInvoice`) | никому как доказательству денег | это UX-статус окна оплаты, а не серверное подтверждение |

Клиент игры присылает **только** результат окна оплаты. Публичных endpoint'ов «зачислить платёж»,
«выдать инвойс на сумму», «вернуть деньги» или «показать журнал» нет: единственный вход для
платёжных эффектов — webhook Telegram, единственный вход для возврата — workflow с секретами.

## Архитектура

```
Telegram ──POST /telegram/webhook──▶ Worker ──▶ D1 (журнал, каталог, настройки)
   ▲                                    │
   └──── answerPreCheckoutQuery / sendMessage ────┘
```

- `src/index.ts` — маршруты и граница HTTP: секрет, лимит тела, JSON, 404/405, `/health`.
  Все остальные пути и методы получают предсказуемый отказ.
- `src/webhook.ts` — обработка update: pre-checkout, успешный платёж, уведомление о возврате,
  `/start`, `/paysupport`. Неизвестные типы update подтверждаются без платёжных эффектов.
- `src/precheckout.ts` — проверка заявки на оплату по серверному каталогу: валюта, сумма,
  payload, плательщик. Каждая неверная ось отклоняется своей русской причиной.
- `src/mini.ts` — входы Mini App: `POST /mini/hello` (заход, регистрация игрока, копия партии)
  и `POST /mini/restore` (перенос по одноразовому токену). Вера только подписи initData.
- `src/initdata.ts` — подпись `Telegram.WebApp.initData` (HMAC по алгоритму Telegram),
  свежесть `auth_date`, токены переноса: 32 случайных байта, в D1 — только SHA-256.
- `src/players.ts` — игроки, сохранения и одноразовые токены. Ограничители напоминаний
  живут в схеме D1: между запусками cron никакой памяти нет.
- `src/reminders.ts` — ежедневный cron «Алик скучает»: выбор молчунов одним SQL, ограничители,
  текст отмазки и две кнопки («Открыть», «Не напоминать»).
- `src/db.ts` — журнал. `charge_id` — `PRIMARY KEY`, вставка атомарная
  (`INSERT … ON CONFLICT(charge_id) DO NOTHING`), поэтому конкурентная доставка не задваивает платёж.
- `src/webhook-secret.ts` — секрет webhook как HMAC от токена бота с постоянным контекстом
  и id бота. Установщик и Worker считают одно и то же значение, поэтому повторный deploy
  не рассинхронизирует `setWebhook` и проверку заголовка.
- `src/telegram.ts` — клиент Bot API: таймауты, проверка и HTTP-статуса, и `{ok:false}`,
  вычистка токена из любых сообщений.

### Платёжный цикл

1. Игрок открывает инвойс, Telegram присылает `pre_checkout_query`.
   Worker проверяет его **до** подтверждения: `currency === 'XTR'`, положительная целая сумма,
   payload `v<версия>:hash-cup:<сумма>` и активная строка каталога. Верная заявка подтверждается
   `answerPreCheckoutQuery(ok=true)`, неверная — `ok=false` с понятным текстом. Внутренний бюджет
   ответа — 3 с (Telegram ждёт 10 с); сетевой таймаут не выдаётся за успех.
2. Telegram присылает `message.successful_payment`. Worker записывает платёж в D1 **до** ответа 2xx.
   Если запись не удалась — отдаёт 503, чтобы Telegram повторил доставку, а не потерял деньги.
   «Спасибо» в чат отправляется после записи; его сбой платёж не теряет.
3. Повторная доставка того же `telegram_payment_charge_id` — `duplicate`. Тот же charge ID с другими
   реквизитами — `conflict` в отдельной таблице, исходная строка не перезаписывается.
4. Деньги, пришедшие по устаревшему/неизвестному счёту, **не теряются**: строка пишется со
   статусом `paid` и `note = 'review: …'` без игровых привилегий. Это видно в `status`.
5. `message.refunded_payment` (если Telegram его присылает) переводит платёж в `refunded`.

### Удержание и перенос партии (#1488)

Оба механизма строятся и проверяются на моках, а включаются, когда у оператора появится бот:
без `BOT_TOKEN` воркер отвечает как обычно (health `503`), а игра без `VITE_TELEGRAM_WORKER_URL`
просто не зовёт `/mini/*`.

**Заход.** Mini App при открытии и при уходе шлёт `POST /mini/hello` с подписанной `initData`,
версией сохранения, самим сохранением (тот же JSON, что лежит в localStorage) и признаком
«партия на экране концовки». Воркер проверяет HMAC-подпись initData, пишет строку в `players`
(визит, концовка, сброс серии напоминаний) и копию партии в `saves`. Тело запроса не называет
игрока: `chat_id` и user id берутся только из подписи.

**«Алик скучает».** Worker Cron Trigger (`0 12 * * *`, `wrangler.json`) раз в сутки выбирает одним
SQL тех, кто не заходил ≥ 2 суток, не отказался, не на экране концовки и получил меньше трёх
напоминаний подряд. Напоминание — одно сообщение от Алика в тоне отмазок, с кнопкой «Открыть»
(ссылка игры) и кнопкой «Не напоминать» (callback `no_remind`): она пишет `opt_out = 1` навсегда,
подтверждает нажатие и убирает клавиатуру. Занёс игрока в игру — `reminder_count` становится 0,
`opt_out` не снимается никогда. Между напоминаниями — не меньше двух суток (`last_reminder_at`).

**Перенос.** `/save` подтверждает последнюю серверную копию, `/load` выпускает одноразовую ссылку
`<GAME_URL>?startapp=<токен>` (токен живёт час, в D1 — только его хеш). Игра на пустом устройстве
показывает «Восстановить партию» и `POST /mini/restore` забирает сохранение **байт в байт** (сверка
сериализации, а не полей). Токен гасится одним `UPDATE … WHERE used_at IS NULL AND expires_at > …`:
два конкурентных запроса не могут оба получить партию, токен чужого игрока не гасится и не отдаёт
чужую строку. Сохранение живёт в D1 как есть: воркер не знает полей партии и не ломается при их
изменении — версию схемы называет игра (`version`).

**CORS.** `/mini/*` отвечают только origin'ам из `CLIENT_ORIGINS` (по умолчанию
`https://enikey87.github.io`). Подпись initData — единственная защита данных; origin нужен браузеру.

### Схема D1

| Таблица | Назначение |
|---|---|
| `catalog` | товар, версия, валюта `XTR`, цена Stars, активность. Серверный источник правды о цене |
| `payments` | журнал: `charge_id` (ключ), Telegram user ID, payload, валюта, сумма, время, статус `paid`/`refunded`, `note` |
| `payment_conflicts` | расхождения: тот же charge с другими реквизитами, возврат по неизвестному charge |
| `settings` | служебное: ссылка инвойса, её сумма и версия каталога — для переиспользования |
| `players` | заходы и ограничители напоминаний: `last_seen_at`, `finished`, `reminder_count`, `last_reminder_at`, `opt_out` |
| `saves` | последняя партия от игры: user ID, `version` схемы, JSON байт в байт, время |
| `transfer_tokens` | одноразовые токены переноса: SHA-256 токена, срок, `used_at` |

Персональных данных минимум: только Telegram user ID плательщика (нужен для возврата) и игрока
(нужен для напоминания и переноса). Переписка, имена и полный raw update не хранятся. Все значения
пишутся параметризованным SQL (кроме установщика, который подставляет только числа и проверенные
строки). В `transfer_tokens` лежит только хеш токена: дамп базы не даёт открыть чужую партию.

## Команды

Нужны Node.js 24+ и npm. Все команды — из `services/telegram-worker/`.

```sh
npm ci                # воспроизводимая установка (без production-секретов)
npm run typecheck     # tsc: Worker и скрипты установщика
npm run lint          # eslint
npm test              # vitest: 129 тестов, из них 92 — на настоящем workerd и D1
npm run build         # wrangler deploy --dry-run (сборка без выкладки)
npm run dev           # локальный Worker на http://localhost:8787
npm run db:migrate:local  # применить миграции к локальной D1
npm run deploy        # установка целиком (нужны секреты, см. ниже)
npm run status        # диагностика установки
npm run refund        # возврат Stars по charge ID (нужно подтверждение)
```

`npm run dev` поднимает Worker с локальной D1 из `.wrangler/`. Секреты для локального запуска
кладутся в `.dev.vars` (в git не попадает), например:

```sh
BOT_TOKEN=000000:local-test-token
WEBHOOK_SECRET=local-secret
```

Локальный Worker не ходит в боевой Telegram: `TELEGRAM_API_BASE` можно направить на заглушку.

## Настройки

| Имя | Где | Что это |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | environment secret | токен Cloudflare: Workers Scripts Edit, D1 Edit, Account Settings Read |
| `CLOUDFLARE_ACCOUNT_ID` | environment variable | Account ID, не Zone ID |
| `TELEGRAM_BOT_TOKEN` | environment secret | токен `@alik_where_money_bot` |
| `BOT_TOKEN` | Worker secret | тот же токен, кладёт установщик |
| `WEBHOOK_SECRET` | Worker secret | производная от токена, кладёт установщик |
| `GAME_URL` | переменная Wrangler | ссылка на игру для `/start` и основа ссылки переноса (`?startapp=…`) |
| `SUPPORT_URL` | переменная Wrangler | куда идти за помощью по платежу для `/paysupport` |
| `BOT_USERNAME` | переменная Wrangler, необязательная | имя бота для ссылки переноса; пусто — берётся из `GAME_URL` |
| `CLIENT_ORIGINS` | переменная Wrangler, необязательная | origin'ы Mini App через запятую; по умолчанию `https://enikey87.github.io` |
| `SAVE_MAX_BYTES` | переменная Wrangler, необязательная | предел тела `/mini/hello`; по умолчанию 512 КБ (сохранение больше платёжного update) |
| `STARS_AMOUNT` | вход workflow | цена Stars, по умолчанию 25 (не рубли) |
| `EXPECTED_BOT_USERNAME` | необязательная env установщика | какой бот ожидается; по умолчанию `alik_where_money_bot` |
| `CONFIRM_REPLACE_WEBHOOK` | необязательная env установщика | `true` разрешает замену чужого webhook |
| `CHARGE_ID`, `REFUND_CONFIRM` | вход workflow `refund` | платёж и его повторное подтверждение |

Значения `BOT_TOKEN` и `WEBHOOK_SECRET` не печатаются ни в логах, ни в summary: установщик
редактирует их в текстах ошибок, а секрет передаётся в `wrangler secret put` через stdin, а не
в аргументах команды.

## Установка (что делает workflow `deploy`)

1. Проверяет входные данные и обязательные настройки; сумма — целое 1..100000.
2. `getMe` и сверка username с `alik_where_money_bot`. Не тот бот — стоп **до** регистрации webhook.
3. `getWebhookInfo`: если уже стоит посторонний endpoint, установка останавливается с инструкцией.
   Замена — только отдельным подтверждением `replace_webhook_confirmed=true`.
4. Ищет D1 ровно по имени `alik-stars`; несколько баз с этим именем — явная ошибка, а не «первая».
   Нет базы — создаёт. Пишет временную конфигурацию с настоящим database ID (в git не попадает).
5. Применяет миграции, затем upsert каталога: та же цена — та же версия; новая цена — версия +1.
6. Выкладывает Worker на бесплатный `workers.dev`, кладёт `BOT_TOKEN` и `WEBHOOK_SECRET`.
7. Проверяет `/health` до готовности (конфигурация + схема D1).
8. Вызывает `setWebhook` с `secret_token`, `allowed_updates: ['pre_checkout_query', 'message', 'callback_query']`
   и **без** `drop_pending_updates`; затем проверяет адрес через `getWebhookInfo`. `callback_query`
   нужен кнопке «Не напоминать»: без него Telegram не доставляет нажатие воркеру.
9. Создаёт `createInvoiceLink` (XTR, один элемент prices, без внешнего payment provider)
   или переиспользует сохранённую ссылку, если сумма и версия каталога не менялись.
10. Пишет в GitHub Summary только публичные значения: адрес Worker, сумму, ссылку инвойса,
    статус и следующий шаг.

Повторный запуск безопасен: миграции не уничтожают данные, журнал не очищается, деньги не
списываются, подписки не создаются. Ошибка любого шага возвращает ненулевой код и называет шаг;
зелёного «готово» при частичном сбое не бывает. Прерванная установка продолжается повторным
запуском с теми же настройками.

После deploy оператор копирует **ссылку инвойса** из Summary в repository variable
`VITE_TELEGRAM_INVOICE_URL` и запускает CI & Pages: фронтенд читает её при сборке. Дополнительный
GitHub PAT не нужен — переменную пишет человек одним копированием.

### Включение «Алика скучающего» и переноса партии (три шага оператора)

Механика уже в воркере и в игре, но молчит, пока нет бота и адреса воркера во фронтенде:

1. Создать бота в BotFather (если его ещё нет) и положить токен в environment secret
   `TELEGRAM_BOT_TOKEN` environment'а `telegram-production`.
2. Запустить workflow **Telegram Stars Worker** в режиме `deploy`: миграции создадут `players`,
   `saves`, `transfer_tokens`, cron `0 12 * * *` поедет вместе с воркером, webhook получит
   `callback_query`. Адрес воркера будет в Summary.
3. Записать адрес воркера из Summary в repository variable `VITE_TELEGRAM_WORKER_URL`, добавить
   её в `env` шага Telegram-сборки `.github/workflows/pages.yml` (рядом с `VITE_TELEGRAM_INVOICE_URL`)
   и пересобрать Pages. Без переменной адаптер не зовёт `/mini/*`, игра работает как раньше.

Проверка после включения: открыть Mini App — в `players` появилась строка с `last_seen_at`; `/save`
в боте подтверждает копию; `/load` на другом устройстве или в приватном окне предлагает
«Восстановить партию» и возвращает ту же партию. Ссылка переноса строится из `GAME_URL`
добавлением `startapp` — если у бота другая точка входа Mini App, поправить `GAME_URL`, а не код.

## Поддержка и возврат

- `/start` — короткое приветствие и ссылка на игру.
- `/paysupport` — русская инструкция: куда написать (`SUPPORT_URL`), что приложить (дату и сумму),
  и явный запрет присылать номер карты, коды и другие платёжные данные.
- Возврат — режим `refund`, вход `charge_id` и `refund_confirm`, который должен совпасть с charge ID.
  Установщик читает `telegram_user_id` из журнала (не из запроса) и вызывает `refundStarPayment`.
  Успех подтверждается в API, затем статус пишется в D1. Таймаут или сбой записи после возврата
  виден как ошибка с инструкцией ручной сверки; повторный возврат того же charge не запускается.

## Обновление цены

`STARS_AMOUNT` в workflow. Установщик поднимает версию каталога, пишет новую строку и выпускает
новый инвойс; старые ссылки перестают проходить pre-checkout (их сумма/версия больше не совпадают
с каталогом). Уже оплаченные старые счета сохраняются в журнале на разбор. Новую ссылку нужно
снова вставить в `VITE_TELEGRAM_INVOICE_URL` и пересобрать Telegram-сборку — это часть контракта
фронтенда, а не автоматика.

## Ротация токена бота и смена секретов

1. Перевыпустить токен в BotFather.
2. Обновить environment secret `TELEGRAM_BOT_TOKEN`.
3. Запустить `deploy` заново: он положит новый `BOT_TOKEN`, выведет новый `WEBHOOK_SECRET`
   из нового токена и перерегистрирует webhook. D1, журнал и инвойс не удаляются.

## Backup, restore и rollback

- Backup: `npx wrangler d1 export alik-stars --remote --output backup.sql --config wrangler.generated.json`
  (файл временный; содержит user ID — не коммитить и не публиковать).
- Restore: `npx wrangler d1 execute alik-stars --remote --file backup.sql --config wrangler.generated.json`.
- Rollback Worker: `npx wrangler rollback --config wrangler.generated.json` — возвращает предыдущую
  версию кода, **не трогая D1**. `wrangler delete` и удаление базы не нужны и в инструкции не
  используются: журнал платежей должен переживать выкладки.
- Смена токена или цены не требует удаления базы. Без `deploy` database ID нигде не сохраняется.

## Troubleshooting

| Симптом | Действие |
|---|---|
| `Cloudflare API отказал (HTTP 403)` | проверить, что токен — `CLOUDFLARE_API_TOKEN`, а не Global API Key; права Workers Scripts Edit, D1 Edit, Account Settings Read; Account Resources включает нужный аккаунт |
| `ожидался бот @alik_where_money_bot` | `TELEGRAM_BOT_TOKEN` от другого бота; взять токен нужного бота в BotFather |
| `у бота уже стоит другой webhook` | понять, чей endpoint; если он больше не нужен — запустить deploy с `replace_webhook_confirmed=true` |
| `health не подтвердил готовность` | открыть `<worker>/health`: он покажет `failed: [bot-token / webhook-secret / catalog / d1]`. Частая причина — миграции/каталог не применились |
| pre-checkout отклоняется «Счёт устарел» | в игре старая ссылка инвойса: обновить `VITE_TELEGRAM_INVOICE_URL` и пересобрать Telegram-сборку |
| `pre_checkout_query` таймаутит | проверить `/health`, квоты Workers и задержку Telegram API; бюджет ответа 3 с из 10 разрешённых |
| квоты Free | Workers/D1 Free имеют суточные лимиты; при их превышении Worker отвечает ошибками. Платный тариф этой задачей не включается |
| ошибка миграции | посмотреть текст `wrangler d1 migrations apply`; повторить deploy — применённые миграции пропускаются, данные сохраняются |
| платёж на разборе | строка со `note = 'review: …'`: деньги получены, позиция не совпала с каталогом. Сверить charge ID в `status` и решить вручную (возврат — режим `refund`) |

## Что проверено автотестами, а что нет

Проверено (`npm test`):

- настоящий entrypoint Worker'а в workerd с настоящей локальной D1 и настоящими миграциями;
- граница HTTP: секрет (нет/неверный/пустой), методы и пути, битый JSON, лимит тела,
  неизвестные update;
- pre-checkout: верная оплата, каждая неверная ось отдельно, HTTP-ошибка API, `{ok:false}`,
  таймаут бюджета, отсутствие записи «оплачен» до `successful_payment`;
- журнал: новый платёж, повтор update, тот же charge под новым update ID, конкурентная доставка,
  два charge одного игрока, конфликт реквизитов, оплата при отсутствующем/изменённом каталоге,
  сбой D1 → 503 и успешный повтор, сохранность после нового запроса;
- возврат: уведомление, повтор, неизвестный charge, сбой D1;
- установщик: чистый и повторный deploy, смена цены, отсутствие настроек, чужой бот,
  посторонний webhook и подтверждённая замена, отказ Cloudflare API, сбой шага, нездоровый Worker,
  отсутствие секретов в аргументах и логах, параметры `setWebhook`/`createInvoiceLink`,
  отсутствие `drop_pending_updates`;
- `status` и `refund` на подменённых Telegram/Cloudflare/wrangler;
- подпись initData: вектор, посчитанный отдельно по алгоритму Telegram; правка байта подписи,
  чужой токен бота, старая `auth_date` — отказ;
- `/mini/hello`: заход регистрирует игрока, сохранение ложится в D1 байт в байт, заход сбрасывает
  серию напоминаний и не снимает `opt_out`, концовка пишется в строку, CORS по списку origin'ов;
- `/mini/restore`: тот же JSON возвращается, токен гаснет на втором использовании, чужой игрок
  не видит чужую партию, просроченный токен — отказ, подпись обязательна и здесь;
- `/save` и `/load`: подтверждение копии, отказ без копии, ссылка `?startapp=` с TTL час;
- cron «Алик скучает»: молчун 3 дня получает одно сообщение с двумя кнопками, вчерашний заход —
  тишина, пауза двух суток, лимит трёх подряд, концовка и `opt_out` — тишина, сбой отправки
  одному игроку не останавливает остальных, пустая база не падает;
- кнопка «Не напоминать» через webhook: `opt_out = 1`, `answerCallbackQuery`, клавиатура снята.

Не проверено и требует оператора: реальная выкладка в аккаунт Cloudflare, боевые права токена,
реальный `setWebhook` у бота и контрольная оплата Stars. Автотесты не обращаются к боевому
Telegram, не создают ресурсы Cloudflare и не списывают звёзды.

## Негативные контроли

Проверены вручную на этой ветке (сломать → красный тест → вернуть):

- убрать проверку секрета webhook → падает тест границы HTTP;
- разрешить любую сумму в pre-checkout → падает тест «сумма отклоняется»;
- заменить атомарную вставку на `INSERT` без `ON CONFLICT` → падает тест конкурентной доставки;
- проглотить ошибку записи D1 и ответить 200 → падает тест повторной доставки;
- включить `drop_pending_updates` в `setWebhook` → падает тест параметров webhook;
- убрать `AND reminder_count < 3` из выбора молчунов → падает «три подряд — дальше тишина»;
- убрать `AND finished = 0` → падает «партия на экране концовки — напоминания нет»;
- убрать `AND used_at IS NULL` при погашении токена → падает «токен гаснет на втором использовании»;
- убрать сравнение подписи initData → падают тесты подписи (подделка, чужой бот);
- убрать `WHERE opt_out = 0` → падают «не напоминать — тишина» и кнопка «Не напоминать».
