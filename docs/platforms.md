# Яндекс Игры, VK и Telegram (мини-приложения)

Веб-сборка GitHub Pages не меняется: `npm run build` без `VITE_PLATFORM`. Платформенные сборки — тот же клиент с другим адаптером (`src/platform/`). Скрипты в `package.json` не добавлялись.

## Сборка

```sh
npm run typecheck
npx vite build                         # веб, dist/
npx vite build --mode yandex --outDir dist-yandex
npx vite build --mode vk --outDir dist-vk
npx vite build --mode telegram --outDir dist-telegram
```

`--mode` читает `.env.yandex` / `.env.vk` / `.env.telegram` (`VITE_PLATFORM`). В веб-бандле нет запроса к `/sdk.js`, нет пакета `@vkontakte/vk-bridge` и нет скрипта `telegram-web-app.js`: ветки вырезаются по константе режима.

Архив для Консоли Яндекса — содержимое `dist-yandex`, `index.html` в корне ZIP. В `index.html` скрипт SDK не вшит: игра грузит `/sdk.js` сама, только в режиме `yandex`.

## Что вызывает адаптер

| | web | yandex | vk | telegram |
|---|---|---|---|---|
| Старт | ничего | `YaGames.init()` | `VKWebAppInit` | `WebApp.ready()`; fullscreen на телефонах |
| Полный экран | системный | — | — | `requestFullscreen()` на телефонах при поддержке; вертикальные свайпы закрыты (Bot API 7.7) |
| После первого кадра | ничего | `LoadingAPI.ready()` | ничего | ничего |
| Игрок может ходить / оверлей или вкладка скрыта | ничего | `GameplayAPI.start()` / `stop()` | ничего | ничего |
| Тема | системная (`prefers-color-scheme`) | системная | системная | `WebApp.colorScheme` (`data-theme` на `:root`) |
| Карточка «займи 50» | внешняя ссылка | инап-покупка «Чашка хаша для Алика» (`payments.purchase()`) | кнопка «Вступить в сообщество игры» (`VKWebAppJoinGroup`) | Stars-инвойс «Чашка хаша для Алика» (`WebApp.openInvoice`), без ссылки и рублёвой суммы (#1235) |
| Прогресс | `localStorage` | облако `player data` (`getData`/`setData`), копия в `localStorage` | `localStorage` | `localStorage` |

Облачный сейв (`src/platform/cloud.ts`, #1240): игра читает прогресс синхронно, поэтому облако стоит за
копией в памяти. `init()` Яндекса читает `getData()` до создания партии; каждая запись сначала ложится в
`localStorage`, потом уходит в `setData(…, flush)`. Две копии (два устройства) разрешаются по времени
последней записи в ключе `alik-cloud-sync`: побеждает более новая, проигравшая называется строкой в
консоли. Отказ SDK, `getPlayer` или самого облака партию не роняет — прогресс остаётся локальным.
Между устройствами едет только прогресс (`alik-save-v4`); отметки устройства остаются на устройстве.

Отказ или зависание SDK (дольше 8 с) не останавливает партию: игра открывается без витринных вызовов. Ссылка на DonationAlerts при этом не возвращается — режим сборки уже не web.

Отладка загрузчика Яндекса: к адресу игры добавить `debug-mode=16`. В левом нижнем углу `W` — ждёт, `IT` — инициализация верна, `IF` — старый лоадер.

## Чек-лист перед загрузкой в Консоль Яндекса

- ZIP, `index.html` в корне, игра открывается в iframe на домене Яндекса.
- В архиве нет абсолютного `https://yandex.ru/games/sdk/v2`: только динамический `/sdk.js` после `init`.
- `LoadingAPI.ready()` — после первого кадра, не до него.
- `GameplayAPI.start()` когда игрок может действовать; `stop()` на интро, досье, экране концовки, севшем телефоне и при уходе с вкладки.
- Нет внешней платёжной ссылки (карточка «займи 50» — инап-покупка или скрыта).
- Покупка: товар «Чашка хаша для Алика» в Консоли, `VITE_YANDEX_PRODUCT_ID` в `.env.yandex`; незакрытые платежи игра закрывает при старте (`getPurchases()` → `consumePurchase()`).
- Облачный сейв: `getData()` до создания партии, прогресс с другого устройства виден при первом запуске.
- Реклама, платежи и лидерборды — не в этой сборке.

## Покупка «Чашка хаша для Алика» (Яндекс Игры, #1241)

Деньги на площадке принимает только SDK (п. 1.4): внешняя ссылка на DonationAlerts на Яндексе невозможна.
Решение оператора по #791 — вариант Б: инап-покупка «Чашка хаша для Алика» через `ysdk.payments`.

- `VITE_YANDEX_PRODUCT_ID` — ID товара из вкладки покупок Консоли. Пусто — товара нет: карточки покупки
  на Яндексе нет вовсе, `getPayments()` не зовётся (как пустой `VITE_VK_GROUP_ID` на VK).
- Цена — из `payments.getCatalog()` (`price`, строка вида `49 YAN`), а не из кода: портальная валюта
  определяется площадкой (п. 1.13.4). Нет цены — кнопки нет.
- Консумирование обязательно (п. 1.13.1): при каждом старте `getPayments()` → `getPurchases()`, покупки
  своего товара закрываются `consumePurchase(token)`; закрытая при старте покупка выдаёт партии тот же
  спонсорский итог, что и «Перевёл» (переименование группы `ПЛИТОЧНИК — СПОНСОР`).
- На ТВ покупки нет (п. 1.6.3.4), но незакрытые платежи закрываются и там — это учёт, а не продажа.
- Ответ на шутку и ачивка «Кредитор Алика» — по-прежнему по выбору игрока; покупка их не подменяет.
- Подпись покупки не проверяется: сервера у игры нет, `signed`-режим — отдельное решение при накрутках.

## VK

Путь — мини-приложение (dev.vk.com), не витрина VK Play. Обязательный вызов на старте — `VKWebAppInit` через `@vkontakte/vk-bridge`. Хранилище, реклама и платежи VK — после этого шага.

Карточка «займи 50» на VK — не донат: внешние платежи на площадке запрещены, поэтому кнопка ведёт в
официальное сообщество игры (`VKWebAppJoinGroup`, бонус за вступление разрешён п. 2.6.2). id сообщества —
`VITE_VK_GROUP_ID` в `.env.vk`, его заводит оператор; пустое значение — карточки на VK нет (сборка
готова, ждёт id сообщества). Успешное вступление выдаёт группе спонсорское имя «ПЛИТОЧНИК — СПОНСОР» (тот же итог, что у
ответа «Перевёл»), отказ не меняет ничего. Ответ на шутку остаётся за игроком, ачивка «Кредитор Алика» —
по-прежнему по ответу.

## Telegram Mini App (#1234)

Сборка — тот же веб-клиент в WebView Telegram. Скрипт `https://telegram.org/js/telegram-web-app.js` грузит
сам адаптер (`src/platform/telegram.ts`), и только в telegram-сборке: веб и витрины его не запрашивают.

- `WebApp.ready()` — на старте. На Android/iOS (`WebApp.platform`: `android`, `android_x`, `ios`)
  игра вызывает `expand()`, затем `requestFullscreen()` (Bot API 8.0), если ещё не на весь экран.
  Web/Desktop остаются в окне; если клиент уже включил fullscreen, игра запрашивает `exitFullscreen()`.
  Неизвестная платформа не разворачивается. Отсутствующий метод или отказ клиента не ломают старт.
- Ссылка из README использует `mode=compact`: Telegram выбирает компактное окно при открытии,
  а мобильный адаптер затем разворачивает игру. Точные размеры окна определяет клиент Telegram;
  настройка относится к запуску по этой ссылке, а не меняет кнопки бота в BotFather.
  Режимы открытия и методы описаны в [документации Telegram](https://core.telegram.org/bots/webapps).
- `disableVerticalSwipes()` (Bot API 7.7) не даёт вертикальному свайпу закрыть игру посреди хода.
- Тема: `colorScheme` клиента ставит `data-theme` на `:root` (палитры — в `styles.css`), `themeChanged`
  переносит её на ходу. Клиент без `colorScheme` определяется по яркости `themeParams.bg_color`.
  Системная тема WebView не важна: телефон у игрока может быть светлым, а Telegram — тёмным.
- Safe area: адаптер ставит `data-platform="telegram"`; стили резервируют системные отступы и место
  под кнопки клиента для телефона и оверлеев. CSS-переменные SDK обновляются при изменении окна;
  системные значения `env()` и SDK учитываются через максимум, отступы интерфейса Telegram добавляются.
- `externalPay: false`: внешняя платёжная ссылка (DonationAlerts) в Telegram запрещена, цифровые товары
  продаются только за Stars. Карточка «займи 50» на Telegram — Stars-покупка (см. ниже, #1235).
- `gameplayStart`/`gameplayStop` — пустые: игрового API площадки у Mini App нет.
- Скрипт не доехал (блокировщик, нет сети) или клиент ответил отказом — партия идёт как обычно, адаптер
  остаётся telegram-адаптером: молчаливый фолбэк на веб вернул бы запрещённую внешнюю ссылку.
- Постоянный URL Mini App (подпуть `/t/` на GH Pages) — задача #1236; CloudStorage/DeviceStorage не подключены.

## Покупка «Чашка хаша для Алика» (Telegram Stars, #1235)

Внешние платёжные ссылки в Telegram запрещены для цифровых товаров: платят только звёздами. Карточка
просьбы «займи 50» на Telegram открывает Stars-инвойс клиента (`WebApp.openInvoice`, Bot API 6.1).

Платёжную часть обслуживает отдельный подпроект
[`services/telegram-worker`](../services/telegram-worker/README.md) (#1415): Cloudflare Worker + D1,
webhook Telegram, журнал платежей и возврат Stars через GitHub Actions. Игра остаётся статической
сборкой; Worker не выкладывает её и не заменяет.

- `VITE_TELEGRAM_INVOICE_URL` — публичная ссылка инвойса, её печатает workflow **Telegram Stars Worker**
  в Summary после deploy; оператор копирует её в repository variable и пересобирает Telegram-сборку.
  Пусто — инвойса нет: карточки покупки в Telegram нет вовсе (`pay50` не появляется).
- Источник правды о факте оплаты — журнал Worker'а, а не клиент: колбэк `paid` служит только
  клиентскому UX (включить спонсорское имя группы), а деньги подтверждает `successful_payment`
  от Telegram, записанный в D1. Локальная награда в партии серверно не защищена и не объявляется такой.
- Цену Stars задаёт каталог Worker'а (вход workflow `stars_amount`), а не код клиента: сумма и валюта
  в карточке не показываются, их называет окно Telegram.
- `openInvoice` отдаёт итог колбэком: `paid` — деньги списаны, окно закрыто/`failed`/`pending` — `closed`.
  Клиент без метода (Bot API < 6.1) и синхронный отказ клиента — тоже `closed`: партия не меняется.
- Текст карточки — `LEND50_TG_SYS`, кнопка «Купить «Чашку хаша»»; ссылки и адреса в разметке нет, суммы в
  рублях тоже: сумму и валюту задаёт инвойс на стороне Telegram, а не код.
- Успех засчитывает то же спонсорское имя группы («ПЛИТОЧНИК — СПОНСОР»), что «Перевёл» на вебе, покупка
  на Яндексе и вступление на VK; отказ не меняет ничего. Ответ на шутку и ачивка «Кредитор Алика» —
  по-прежнему по выбору игрока.

## Чего сборка не делает

CI по-прежнему собирает только веб. Загрузка в консоли площадки и выкладка Telegram-сборки в `/t/` (#1236) — вручную, этими командами. Реклама, лидерборды и облачный прогресс — не в этой сборке.
Платёжные деньги Telegram считает отдельный сервис `services/telegram-worker`, но игровых благ он не
выдаёт: клиент по-прежнему засчитывает покупку локально, серверного сейва и серверных наград нет.
