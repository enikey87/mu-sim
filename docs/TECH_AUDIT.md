## Открытые и принятые

### P3-3. Бандл 781 kB одним чанком (239 kB gzip) — принято, кроме варианта 2

Замерено `npm run build`. Почти всё — контент (тексты отмазок, сцен, сериалов). Для браузерной шутки приемлемо; на медленной сети ~1–2 с только JS. Warning >500 kB не глушить — он единственный сторож роста.

Остаётся развилка: dynamic import контента третьего акта (`payday`, `finales`) — реальная экономия, но контент синхронный (`game.ts` дёргает его напрямую), асинхронность пролезет в движок. `manualChunks` (react vendor) — косметика, gzip-итог тот же.

### P3-6. Две версии TypeScript — принято

`package.json`: typecheck — `typescript-7` (`npm:typescript@7.0.2`), ESLint — `typescript` = `@typescript/typescript6@6.0.2` (typescript-eslint пока не умеет TS 7; README это описывает). Два компилятора могут расходиться в диагностике; каждый бамп — двойной. Следствие: `npx tsc` вызывает TS 6, проверка типов — только `npm run typecheck`. Убрать alias, когда typescript-eslint поддержит TS 7 (issue-напоминания нет).

### P3-7. `game.ts` — 1735 строк, god object

Один класс держит: конвейер сообщений, аудио, батарею, сборку вариантов, сцены, сериалы, бухгалтерию лжи, концовки, idle-жизнь, эндгейм, персистентность. Первый кандидат на вынос сделан в #50, но только наполовину по смыслу: в `ui-state.ts` (27 строк) переехали **поля** (status, typing, toast, notif, moos, busy, unread, feel, trace, sheetOpen); **поведение** осталось в `Game` — `flash`, `notify`, `feelFor`, поля wall-таймеров `toastWall`/`notifWall` (всё в `game.ts`). `game.ts` уменьшился на 20 строк.

- ✅ Батарея/зарядка вынесены в `engine/battery.ts` (issue #57, PR #66): уровень (`S.battery`, формат сохранения прежний), флаги `dead`/`charging`, `drain`/`die`/`charge`. `Game` — точки вызова и колбеки `BatteryHost` (уведомления, таймеры, ачивки, сохранение, пачка непрочитанных после зарядки). Партии побайтово совпадают с ревизией до выноса (сиды 7771–7773).
- ✅ Два контура времени разведены типами (#61): игровые таймеры — `GameTimer` (`Clock`), настенные (`toastWall`, `notifWall`, `audio.trackTimeout`) — `WallTimer` (`wallClock`); перепутывание — ошибка компиляции, сторож `@ts-expect-error` в `clock.test.ts`.
- Разовый сплит на `engine/{turns,scenes,arcs,lies,endings}.ts` — дорого, дифф-шум, выгода отложенная.

### P3-2. `loadState`: shallow merge без валидации типов — исключено решением оператора (2026-09-22)

Находка верна: `loadState` (`src/engine/state.ts`) — `{ ...freshState(), ...s }`; вложенные объекты (`stats`, `rules`, `mem`) заменяются сохранением целиком, поле, добавленное внутрь вложенного объекта, у старого сохранения будет `undefined` (прецедент — `rules.said ??= {}` в конструкторе `Game`); битые типы (`debt: "abc"`) протекают в игру. Сейчас спасает бамп `SAVE_KEY`. В работу не берётся.

### Ручная инкрементальная синхронизация ленты — принято

`syncMessageNodes`, `MessageList` (`src/ui/Chat.tsx`): creation/sync O(Δ), родитель всё ещё видит до `LIVE_RENDER_CAP = 1000` детей. Не трогать до следующего удара о frame time; тогда — виртуализация, а не третий слой ручного кэша (см. `TECH_DEFECTS.md`).
