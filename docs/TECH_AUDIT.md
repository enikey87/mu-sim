## P1-1. Софт-лок при неожиданной ошибке: флаг `busy` не сбрасывается

**Проблема.** Три entry point'а ставят `busy = true` и сбрасывают его внутри `try`, а не в `finally`. Любая ошибка, кроме `GameDisposed`, оставляет `busy = true` навсегда: `send`, `answerJob`, `onIdle` после этого молча выходят в начале — игра встаёт до перезагрузки страницы. `swallowDisposed` перебрасывает такие ошибки дальше, UI вызывает `void game.send(...)` — дополнительно unhandled promise rejection.

**Где (прочитано в коде):**
- `src/engine/game.ts:842` (`busy = true`) → сброс на `:938` внутри `try`; `finally` на `:943` сбрасывает только `inPlayerTurn`
- `src/engine/game.ts:1440` → `:1458` (`answerJob`), `src/engine/game.ts:1478` → `:1487` (`onIdle`)
- Источники таких ошибок существуют: `draw` бросает при исчерпанной колоде (`game.ts:262`), guard глубины цепочки триггеров бросает (`src/engine/rules/ruleset.ts:215`), любой TypeError в контентном `respond` (например, `catchLie.offer!` на `game.ts:764`, если у правила уберут `offer`, — линтер это не поймает: он требует `respond` **или** `offer`, `src/engine/rules/lint.ts:25`)

**Варианты:**
1. ✅ **Прагматичный:** `try/finally { busy = false; inPlayerTurn = false }` в `sendTurn`, `answerJob`, `onIdle` + `console.error` в `send`. ~15 строк, логика не меняется.
2. Общий хелпер `withBusy(fn)` — одна точка, но рефакторинг трёх методов ради одной строки каждый.
3. Глотать все ошибки молча — **не делать**: контентные баги сейчас хотя бы видны в консоли.

**Негативный контроль для фикса:** тест — правило с `respond`, бросающим `Error` → после `send` игра принимает следующий ход, ошибка залогирована.

## P2-1. e2e гоняются против dev-сервера, а не прод-сборки

**Закрыто (#44).** `webServer` собирает `dist/` и подаёт его через `vite preview --strictPort`; `reuseExistingServer` теперь `false` — при `!process.env.CI` Playwright проверяет порт **до** запуска команды и молча усыновляет чужой сервер, ничего не собирая. Новый тест в `tests/e2e/ui.spec.ts` краснеет, если отвечает dev-сервер (в сборке грузится `./assets/index-<хеш>.js`, в dev — `/src/main.tsx`), — откат команды не проходит незамеченным.

**Проблема.** `playwright.config.ts` (`webServer.command`: `npm run dev`) — e2e проверяют дев-сборку. На Pages уходит `dist/` из `vite build` с `base: './'` и минификацией: класс ошибок «в dev работает, в проде нет» (base path, отсутствие dev-варнингов React, иная нарезка чанков) e2e не видит.

**Варианты:**
1. ✅ **Прагматичный:** `webServer.command`: `npm run build && npm run preview -- --host 127.0.0.1 --port 4173`. CI уже собирает — шаг `build` поднять выше e2e, `dist` переиспользуется.
2. Отдельный playwright-проект «smoke-prod» рядом с dev-прогоном — двойное время CI.
3. Оставить — если договориться, что e2e проверяет только логику, а сборку сторожит сам шаг `build` (он падает при синтаксических проблемах, но не при рантайм-различиях).

## P2-3. Горячий путь `facts()`: полная пересборка на каждый `draw`

**Опровергнуто замером (2026-09-22), обе посылки неверны.** `facts()` стоит 0.011 мс на вызов при пустом журнале обещаний и 0.017 мс при 400 подставленных (переписка 231 сообщение), 0.015 и 0.020 мс при 924 сообщениях. За ход: 0.43 мс на первом, 0.13 мс на 400-м — рост не вверх, а вниз (вызовов за ход 15 → 6). Журнал обещаний к 431-му ходу — **25**, а не «сотни»: чистки в `recordPromise` нет, но и поводов для сотен контент не даёт. Квадратичное слагаемое в коде есть, его основание — 25, а цена вызова на три порядка ниже оценки из находки. Мемоизация `facts()` добавила бы поверхность инвалидации кэша без измеримой выгоды.

**Проблема (прочитано в коде, не замерено).** `lineFacts()` (`game.ts:265`) вызывает `facts()` (`:638`), а её — каждый `draw`/`decks.pick` с гейтами: за один ход Алика (генератор отмазок, декораторы, выбор реплик) это десятки вызовов. Внутри `facts()` — `topicOfLast()` (`:690`): скан сообщений с конца + `split/join` по **каждому** обещанию из журнала (`:699`). Журнал обещаний не чистится (`recordPromise`, `:952` — только push), то есть стоимость хода растёт квадратично с длиной партии: ~(вызовы за ход) × (обещания). Оценка по коду: сотни обещаний к 400-му ходу → единицы–десятки мс на ход; на слабом мобильном заметно.

**Варианты:**
1. ✅ **Прагматичный:** мемоизировать `facts()` по дешёвому ключу (`msgs.length`, id последнего сообщения, `promises.length`, ссылка `ctx`, `day`, `stats.sent`) с инвалидацией в `push`/`replaceMsg`; либо кэшировать только `topicOfLast` по тому же ключу.
2. Ленивые поля через Proxy — меняет семантику `Facts` (плоский объект), рискованно.
3. Ничего не делать и пересмотреть при первом реальном торможении — честный вариант, но квадратичный множитель никуда не денется.

**Проверка для фикса:** бенч-замер хода на партии 450 ходов до/после (playtest-бот уже умеет воспроизводимые партии по seed).

## P3-8. Слепые зоны playtest-бота: 62 правила ни разу не сработали

**Закрыто (#45), диагноз находки был неверен.** Различие «мёртвое правило / симуляция не доходит» существовало и работало: гейт в `tools.test.ts` требовал, чтобы каждое несработавшее правило было в `RARE`, в наборах стиля и эндгейма или под префиксом `Finale|Ending|Payday|Quiet_`, — но жило в тесте, а не в выводе. Классификация переехала в `coverage.ts`, отчёт печатает группы с указанием прямого теста: `редкие 12 · детерминированные 23 · только в финалах 29 · необъяснённые 0` (всего 64; почему больше 62 — ниже).

Настоящая дыра была одна и не та, что названа: бот шлёт только готовые варианты и **никогда не печатает текст**, поэтому классификатор ввода не имел в симуляции покрытия вовсе — `Says_request`, `Says_request_tone_rude`, `Tone_ViolentThreat`, `Tone_Intimidation`, `Says_moo` были недостижимы по построению. У `botTurn` появился опциональный шанс свободного ввода (фразы из корпуса `input.test.ts`), прогон покрытия его включает; выключить его теперь нельзя молча — гейт падает на этих четырёх. «Бот не мычит» из находки не подтвердилось: «Мууу» редок потому, что симуляция идёт без таймеров (`noTimers`), а `Says_catchLie_*` — из-за совпадения состояния лжи, часть из них срабатывает. Список из 60 стал 64 не по качеству: 11 правил вышли, 15 вошли, и пять правил финалов просто перестали попадать под удачу фиксированных сидов (прямые тесты у них на месте).

Осталось отдельной задачей: `RARE` протух — см. **P3-10**.

**Проблема (наблюдалось в прогоне).** `npm run rules:report` (симуляция 7 партий ботом): «Ни разу не сработали (62)» — среди них `Tone_Cow`, `Says_catchLie_*`, `Opt_Cow`, `Turn_WhileDead`, `Quiet_Dead_*`. Часть — редкие по замыслу (`Quiet_Dead_*` требуют состояния «Алик умер»), но заметная доля недостижима для текущих профилей бота: он не мычит и не ловит Алика на лжи. Читатель отчёта не может отличить «мёртвое правило» от «бот так не играет» — ценность инструмента подмыта.

**Варианты:**
1. ✅ **Прагматичный:** добавить боту недостающие поведения по дешёвому: если среди choices есть `act: 'catchLie'` или `act: 'moo'` — брать с небольшим шансом; профиль «hothead» и так грубит. Порог «не сработало» в отчёте не вводить — оставить глазами.
2. Пометить в отчёте правила, недостижимые текущими профилями (ручной список) — быстро, но список протухнет.
3. Принять: отчёт читает автор, который знает профили бота.

## P3-10. Список `RARE` протух: исключения переживали свои причины

**Закрыто (#48).** Замер по трём непересекающимся выборкам (16 партий × 500 ходов каждая): из 23 записей **10 срабатывают устойчиво** (во всех трёх), 7 — по удаче (в одной-двух), 6 — ни в одной. Первые десять вычеркнуты; у остальных причина переписана фактом («в одной-двух выборках из трёх») вместо сюжета про то, почему не выпадут, — сюжеты и протухли. Все прямые кейсы в `rare.test.ts` сохранены: тесты развязаны со списком (кейс на правило + отдельная проверка «у каждой записи `RARE` есть кейс»), поэтому чистка не стоила ни одного теста. Премиса списка теперь **проверяется, а не подразумевается**: `npm run rules:stable` — отдельный шаг CI — падает, если запись начинает срабатывать во всех выборках, и называет её по имени. Набор гейта покрытия входит в тройку выборок, поэтому всё, что проверка требует вычеркнуть, по построению остаётся достижимым для гейта. **Негативный контроль:** возвращённый в список устойчивый `Scene_lend` даёт падение ровно на `['Scene_lend']`.

**Проблема.** Запись в `RARE` — это не описание, а выключенное требование: пока правило в списке, гейт покрытия не пожалуется, если симуляция перестанет до него доходить. Премису («симуляция доходит не всегда») утвердили один раз руками, и ничто её не перепроверяло, поэтому список накопил записи, которые давно срабатывают устойчиво, а комментарии рядом называли причины, которых больше нет. Замер по одной выборке этот дрейф **не** показывает: попадание в неё неотличимо от покрытия — на одной выборке «протухшими» выглядели 11 записей, на трёх устойчивыми оказались 10.
