# Алик, Где Деньги? 🐄

Симулятор переписки с подрядчиком, который не платит. Гэг, выкрученный до абсурда.

*Основано на реальных событиях. Но все реальные совпадения случайны.*

**[▶ Играть в браузере](https://enikey87.github.io/mu-sim/)**

## Диалог по фактам: от GDC до неоплаченной плитки

В игре реплики выбирает локальный движок правил. LLM во время партии не вызывается: тексты,
шаблоны и условия уже лежат в коде. Стек — **TypeScript, React и Vite**, игровой бэкенд не нужен,
прогресс хранится в `localStorage`.

Основа — подход Valve: событие собирает факты о мире, движок выбирает самое специфичное
подходящее правило, ответ меняет память и запускает следующие события. Специальный случай
добавляется своим правилом. Приоритеты речи, перерывы и память помогают удерживать разговор,
когда несколько сюжетных линий претендуют на один ход.

Вдохновение движка — диалоговые системы из этих докладов:

| Доклад | Что интересно для проекта |
|---|---|
| [AI-driven Dynamic Dialog through Fuzzy Pattern Matching. Empower Your Writers!](https://www.gdcvault.com/play/1015946/AI-driven-Dynamic-Dialog-through) — Elan Ruskin, Valve, GDC 2012 | Left 4 Dead: выбор ответа по фактам, переход от частного случая к общему, контент без разрастания `if/else`. У Valve слайды называются [Rule Databases for Contextual Dialog and Game Logic](https://www.valvesoftware.com/en/publications). |
| [A Context-Aware Character Dialog System](https://www.gdcvault.com/play/1020951/A-Context-Aware-Character-Dialog) — Jason Gregory, Naughty Dog, GDC 2014 | The Last of Us: знания отдельных персонажей и общее состояние мира как контекст разговора. |
| [Do You Copy? Dialog System and Tools in Firewatch](https://www.gdcvault.com/play/1024415/Do-You-Copy-Dialog-System) — William Armstrong и Patrick Ewing, GDC 2017 | Firewatch: управление состоянием, прерываниями и потоком данных в диалогах. |

Отдельный ориентир — **Hades**: у реплики есть условия, приоритет и память о том, звучала ли она.
Так Алик может вспомнить конкретный эпизод твоей партии, когда для этого появился повод.
При переносе подхода в TypeScript ориентиром также служил `gorecode/kawaii-doom`.
Реализация — в [engine/rules](src/engine/rules/), выбор реплик — в [lines.ts](src/engine/rules/lines.ts).

## Что ещё под капотом

- **Мир отдельно от формулировок.** Появление персонажа, его положение и наступление срока —
  факты на доске памяти. Реплики объявляют, какие факты им нужны: кто уже знаком игроку,
  что случилось в его партии и какой срок наступил по игровому календарю.
- **Бухгалтерия лжи.** Реплика явно помечает своё утверждение. [Типизированный журнал](src/content/ledger.ts)
  хранит, кто что сказал, и различает противоречие и объяснённую смену обстоятельств.
  Поимка на лжи опирается на эти записи, поэтому опечатка в сообщении не меняет его смысл для движка.
- **Воспроизводимые партии.** В тестах случайность задаётся сидом, действия бота записываются.
  На той же версии кода можно [переиграть партию](src/tools/playtest.test.ts) и разобрать,
  откуда взялся неуместный ответ. В игре `?debug` показывает факты, кандидатов и причину выбора правила.
- **Проверяется и достижимость контента.** Боты играют партии; [проверка покрытия правил](src/tools/coverage-gate.test.ts)
  требует, чтобы правило сработало в выборках либо имело прямой тестовый сценарий.
  Линтеры ищут неизвестные факты и недостижимые правила, оракул — нарушения в расшифровках и кадрах мира.
  Vitest проверяет движок и контент, Playwright — интерфейс на настольном и мобильном Chromium.

## Сделано роем агентов. Под присмотром человека

Значительная часть кода и контента создана роем AI-агентов. Они берут задачи из GitHub Issues,
работают в отдельных ветках, пишут тесты и доводят PR до зелёного CI. Протокол работы лежит
в репозитории: [agent-task](.claude/skills/agent-task/SKILL.md) и [agent-task-loop](.claude/skills/agent-task-loop/SKILL.md).

Человек задаёт тон, принимает продуктовые решения, играет и оставляет замечания. Находки из живых
партий идут в задачи, редакторские правки и инструкции следующего аудита. Между ними работают
автоматические прогоны, слепой рецензент-агент и проверка его выводов по коду.

Зелёные тесты умеют подтвердить сумму перевода. Что реплика смешная и звучит по-русски,
всё ещё приходится решать человеку. История этой работы открыта: [аудиты PR](docs/audit-log.md),
[разборы партий](docs/PLAYTEST_ISSUES.md), [редакторский аудит](docs/RUSSIAN_CONTENT_AUDIT.md).

## Запустить локально

Нужны **Node.js 24+** и npm.

```sh
npm ci
npm run dev
```

Открыть адрес из вывода Vite (обычно `http://localhost:5173`).

```sh
npm test           # тесты
npm run lint       # линтер
npm run build      # проверка типов и сборка в dist/
```

Подробные команды, браузерные тесты и плейтесты — в [памятке разработчика](docs/DEVELOPMENT.md).
Механики описаны в [DESIGN.md](DESIGN.md), документы отдельных решений — в [docs/design](docs/design/README.md).
