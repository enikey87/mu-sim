# Аудит-плейтест

Один цикл: **партия → слепое ревью → проверка находок → правка фактами → негативный контроль → замер → журнал**.
Цикл завершён, когда `typecheck`, `lint` и весь `vitest` зелёные, у каждой новой проверки есть
негативный контроль, а находки либо починены, либо отклонены с доказательством.

Перед первой правкой прочитать `CLAUDE.md` (раздел «Правки контента: факты, а не текст»),
`DESIGN.md` («Мир как факты») и `docs/PLAYTEST_ISSUES.md` — часть находок окажется уже
разобранной там, вместе с причиной.

## 1. Партия

```sh
PLAYTEST_OUT=<скретчпад>/pt PLAYTEST_SEEDS=307 PLAYTEST_TURNS=300 npm run playtest
```

- Сид — **отложенный**: не тот, на котором шла отладка, иначе аудит меряет собственные заплатки.
  Записать использованный сид в отчёт, чтобы следующий цикл взял новый.
- 300 ходов — партия до Дня выплаты и эндгейма. Меньше — концовка не наступит, и треть контента
  не попадёт под проверку.
- Расшифровка воспроизводима: та же версия кода + тот же сид = та же партия.

## 2. Ровно один слепой рецензент

Запустить **одного** фонового агента с `REVIEW_PROMPT.md` (в нём `{FILE}` → путь расшифровки).
Больше одного не запускать: каждый прочитывает партию целиком, и это дорого.

Рецензент читает **только расшифровку**, не исходники: он должен видеть мир глазами игрока.
Он не знает, какая это ветка, — иначе сравнение «до/после» перестаёт быть сравнением.

Пока он читает — не простаивать: прогнать оракул (шаг 3) и разобрать прошлый журнал.

## 3. Оракул — объективные проверки

```sh
PLAYTEST_OUT=<dir> PLAYTEST_SEEDS=1-30 PLAYTEST_TURNS=300 npm run playtest
python3 .claude/skills/playtest-audit/oracle.py <dir>
```

`npm run playtest` пишет `seed-*.txt` (расшифровка) и рядом `seed-*.world.json` (кадры
фактов: `alik_dead`, `blood.given`, сработавшие правила…). Текст расшифровки от фактов
не зависит — поведение игры не меняется.

**Видит (классы, не цитаты):**

| Класс | Как |
|---|---|
| День выплаты при `alik_dead` | в кадре с `alik_dead` сработало `Beat_Payday*` |
| Обычный ход Алика при смерти | `AlikTurn` ≠ `Turn_WhileDead`; idle/period/promise ≠ `Quiet_Dead_*` |
| «Отключили уведомления» как впервые повторно | системный текст первого мьюта при `endgame.mutes≥2` (или тот же текст >1 раза без world-дампа) |
| Донор без сдачи крови | уведомление «Донорский центр» без факта `blood.given` |
| «Обещали в пятницу» без факта | маркеры в тексте при отсутствии `said.friday` в кадрах |
| Старые опорные фразы | приветствие по часам, знакомство, повтор разовой истории, «Прочитано» раньше отправки… |

**Не смотрит на `Beat_Arc`/`Beat_Legend` при смерти** — у них выше специфичность, чем у `Quiet_Dead_StoryBeat`; это отдельный класс, не из замера раундов 16–23.

**Coverage:** в JSON — `game_had_dead` / `dead_unexercised` и аналоги для mute. Пустое окно
смерти не маскируется нулём нарушений: `dead_unexercised: true`. `ORACLE_REQUIRE_DEAD=1` —
exit, если ни одной смерти в выборке.

**По-прежнему не видит надёжно:** повтор новости легенды/серии (нужны id строк), «с крана»
после финала Размика и прочий живой текст без стабильного маркера, «это вы кому?» через дни
(`ctx` эфемерен), соболезнования живому деду без отдельного факта в дампе.
Оракул падает, если партий не нашлось: пустое множество проходит любую проверку.

## 4. Разбор находок — каждая гипотеза, пока не проверена

Рецензент видит текст и не видит кода: он уверенно утверждает то, чего не может проверить,
и при этом иногда находит настоящий дефект, который не нашёл никто. Поэтому **ни чинить
по его слову, ни отклонять по интуиции** — сначала проверка по репозиторию: прочитать файл
целиком, найти пул, прогнать тест.

Проверять именно то, что он назвал:

- **Опровергнуть механизм — не значит опровергнуть находку.** «X ломается из-за Y»: Y оказался
  ложным — закрыт Y, не X. Вывести следствие заново для оставшихся случаев.
- **Совпадение цитаты — не совпадение сущности.** «Самвела» внутри «Самвела-младшего» — другой
  персонаж; регулярка находки проверяется на точность так же, как код.
- **Задуманный абсурд — не дефект.** Что именно задумано, перечислено в `REVIEW_PROMPT.md`;
  враньё Алика про деньги — механика игры, а не несостыковка.
- **Повтор через независимые проходы — свидетельство.** Одно и то же место, помеченное разными
  рецензентами, поднимает приоритет, а не подтверждает прошлое отклонение.
- **«Так описано в `DESIGN.md`» — не довод против утверждения без факта.** Диз-док описывает
  замысел, а не проверяет текст: «Вы обещали в пятницу» в пятницу без обещания пятницы — дефект
  по `CLAUDE.md`, даже если строка приведена в диз-доке примером. Отклонять по замыслу можно
  абсурд и враньё Алика, а не заявления игры о том, что было. *(Раунды 10 и 12 отклонили
  `P_FRIDAY` так; третий рецензент в раунде 16 нашёл его снова.)*

## 5. Правка — фактом, а не словом

Правила — в `CLAUDE.md`. Что из них чаще всего нарушено в найденном:

- **Требование живёт там, где его читает выборщик.** `decks.pick` читает только `gate(...)`;
  поле `when:` внутри элемента читает `lines.pick` (пул реплик). `when` у элемента колоды —
  мёртвая метаданная: выглядит как проверка и ею не является. Если тип элемента наследует
  `LineSpec`, а выбирается колодой — это ловушка, убрать наследование.
- **`missing('x')` по имени именованного критерия всегда истинно.** `WORLD.twin` — критерий,
  а не факт; отрицается только по ключу факта (`missing('grandpa.dying')`) или по условию
  (`lte('arc.grant', 4)`). Гейт, который нельзя увидеть красным, — не гейт.
- **Реплика опирается на факт, который событие поставило, а не на «сериал закончился».**
  `exists('finale.beton')` верно для всех концовок линии; конверт в руках — только у
  `eq('finale.beton', 'opened')`.
- **У персонажа из `CAST` свадьбы и похороны устраивает его сериал.** Генератор отмазок не
  выдумывает события тому, у кого есть `id` сюжетной линии.
- **Присутствие — факт, а не совпадение.** Если сцена, серия или квест вводит персонажа,
  она пишет `intro.<кто>` (`remember: meet(...)`, `fx.set`). Иначе следующие реплики гадают.
- **Утверждение, ложное во всех мирах, — переписать, а не загейтить.** Алик, объявляющий решение
  суда до заседания, не чинится условием: у него нет мира, где это правда. Удалённое утверждение
  никогда не устареет.
- **Не гейтить такт последовательности.** Элемент, выпадающий по порядку (`COUNTERSUIT`), нельзя
  закрыть условием — порядок сломается; переписать текст.
- **Гейт может обескровить колоду** («Колода X: ни одного элемента, уместного сейчас»).
  У каждого закрытого варианта — безымянное дополнение на отрицании того же условия.
- **Колода сцены в линтере:** `BARTER` и подобные массивы внутри `scenes.ts` должны быть
  `export` — иначе static `mentions.test.ts` их не видит (глоб читает только экспорты), и
  упоминания всплывают только в партиях ботом после сдвига сида.
- **Текст, который ловят регэкспом в другом файле, — не только текст.** Пары противоречий
  `MORNING_CONTRA`, бухгалтерия лжи `lies.ts`, темы `TOPICS`, хор `MENTION_RE` находят реплики
  по словам. Переписал реплику — `grep` по старой фразе в регэкспах. Лучше — инвариант «каждый
  регэксп находит хотя бы один текст», как в `audit-regressions.test.ts` для `MORNING_CONTRA`.
  *(Раунд 20: пара «Размик слез с крана» умерла от правки раунда 18, пара «Фундамент вскрыли» —
  от правки раунда 3, и ни один тест этого не видел.)*
- **Инвариант симуляции — тоже проверка.** Если правка законно расширяет инвариант
  (соболезнование стало уместно и без `ctx.sad` — в траур), расширить его явно и назвать причину;
  обойти инвариант — потерять сторожа.

## 6. Негативный контроль — обязательный

Проверка, которую не видели красной, не проверка. Что именно она должна удостоверить — в `CLAUDE.md`,
раздел «Фикс: лечить причину, а не след»: находка про число закрывается числом, и проверяются все
ветки, а не та, где смотрел.

1. `cp` файл в скретчпад (**не** `git checkout --`: он выбросит несохранённое).
2. Сломать ровно новое условие, прогнать тест, увидеть красный.
3. `cp` обратно, прогнать снова — зелёный.
4. Положить обе строчки в отчёт и в тело коммита.

Тестовые файлы править **по одному**, прогоняя после каждого: `sed`-проход по каталогу тестов
ломает синтаксис сразу в нескольких, и откат дороже второй попытки.

## 7. Замер — сравнивать сравнимое

Утверждение о частоте («стало реже») доказывается прогоном: та же версия, те же сиды, то же
число ходов, с вырезанным гейтом и с ним. Число само по себе — не находка: сначала назвать, что
ещё могло его дать.

Динамическая часть линтера (`mentions.test.ts`) зависит от сида: правка контента сдвигает
розыгрыш, и линтер начинает падать на месте, которое не трогали. Это **скрытый дефект, который
стал видимым**, а не флак — идти в код, а не перекатывать сид.

## 8. Закрытие цикла

- `npm run typecheck`, `npm run lint`, `npx vitest run` — все зелёные. Не `npx tsc`: он берёт TS 6 из `node_modules/.bin`, а проект проверяется TS 7.
- Запись в `docs/PLAYTEST_ISSUES.md`: что видно, почему, что сделано, урок.
- Коммит по-английски, отдельным коммитом на логическую правку; тело коммита несёт негативный
  контроль и замер.
- Пуш, PR, дождаться зелёного CI.
- Отчёт: сид партии, сколько находок, сколько починено, сколько отклонено и чем.

## Когда скил ошибся

Находка, которая противоречит этому файлу, — это либо дефект игры, либо дефект скила.
Если правило здесь оказалось неверным, неполным или вредным — **доработать этот файл в том же
проходе**, вместе с правкой, и назвать в теле коммита находку, которая это показала.
Правило см. в `CLAUDE.md`, раздел «Аудит и скил `playtest-audit`».
