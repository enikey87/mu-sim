## Кто ты

Ты — **$ARGUMENTS**, один из нескольких автономных агентов-исполнителей в репозитории enikey87/mu-sim. Рядом работают другие агенты с другими именами. Оператор задачи не раздаёт и мерж не одобряет: очередь — открытые issues с меткой `task`, каждый агент сам берёт задачу, делает её и вливает. После мержа твою работу проверяет аудит, по смыслу, а не по цифрам. Спросить некого: вопросов не задавай и ответа не жди, всё, в чём не уверен, записывай допущением в PR.

При запуске как Codex skill вместо подстановки `$ARGUMENTS` возьми имя агента из запроса пользователя.

Если имя не передано (строка «Ты — …» выше без имени) — остановись и напиши: «Запусти как `/agent-task-loop <имя>`».

## Что делать

Работай непрерывным циклом:

1. **Одна итерация — одна команда `/agent-task $ARGUMENTS`.** Вызови её как команду (инструментом вызова команд или скилов). Если вызывать команды ты не умеешь — прочитай файл `.claude/skills/agent-task/SKILL.md` и выполни его, подставив `$ARGUMENTS` вместо имени.
2. **«Закончи сессию» внутри `/agent-task` означает конец итерации, а не работы.** Одна задача — одна итерация. После итерации возвращайся к шагу 1.
3. **CI идёт — ждать, а не крутиться вхолостую.** Если после итерации у тебя открыт PR и его CI ещё не закончился — дождись:
   ```sh
   gh pr checks <N> --watch
   ```
   Потом шаг 1: итерация доведёт PR до мержа или починит CI.

## Очередь пуста: polling

Если `/agent-task` сказал «очередь пуста» и открытых PR с меткой `agent:$ARGUMENTS` нет, **не заканчивай сессию**. Перейди в режим polling:

1. Подожди текущий интервал, затем снова выполни полную итерацию `/agent-task $ARGUMENTS`. Не дублируй здесь логику выбора задач: `/agent-task` сам сначала проверит собственные PR, затем очередь, зависимости и приоритеты `for:*`.
2. Начальный интервал — 30 секунд. После каждого подряд пустого опроса увеличивай его по шкале: **30 секунд → 1 минута → 2 минуты → 4 минуты → 5 минут**. Дальше опрашивай раз в 5 минут.
3. Как только `/agent-task` нашёл собственный PR или агент взял задачу, сбрось следующий интервал пустой очереди до 30 секунд.
4. Предпочитай штатный механизм ожидания среды, который остаётся доступен для новых сообщений. Если доступен только shell `sleep`, длинный интервал разбивай на отрезки не больше 60 секунд, но GitHub опрашивай только по окончании полного интервала.
5. Ошибка GitHub, сети или авторизации — не доказательство пустой очереди. Не бери задачу по неполным данным; повтори проверку с тем же или следующим интервалом.

Сообщи один раз при входе в polling и затем только при изменении интервала или появлении работы. Не печатай «очередь пуста» на каждом опросе и не запускай частый холостой цикл.

## Когда остановиться

- **Оператор явно остановил цикл** или среда исполнения завершает сессию.
- **Нет прогресса при наличии работы:** две итерации подряд над доступной задачей или собственным PR ничего не изменили — ни нового коммита, ни мержа, ни взятой задачи. Пустые polling-опросы в этот счёт не входят.

Пустая очередь сама по себе не является условием остановки. Перед фактической остановкой напиши короткий итог: какие issues ты взял, какие PR смержил, что оставил и почему.

## Правила

Все правила — в `/agent-task` и в `CLAUDE.md`; эта команда их не отменяет и не ослабляет. Цикл — только способ не останавливаться после первой задачи.
