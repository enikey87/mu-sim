# Скилл: исчерпание пула (pool exhaustion)

Класс проблем: **рекуррентный момент игры × источник без разнообразия**. Момент повторяется
по механике (цикл блок-анблок, истечение терпения, недельная сводка), а строка для него одна
или пул мал для каденции — живой игрок видит одну и ту же реплику раз за разом. Слепой
ревьюер это ловит редко (его окно — одна партия, момент может прийтись редко), оракул — не
ловит вовсе (его повторы считаются по событиям уведомлений, не по репликам). Ловит только
**профильное давление**: специализированная партия, которая входит в цикл и живёт в нём.

## Таксономия источников

| Тип | Признак | Пример | Тяжесть |
|---|---|---|---|
| HARDCODED | `export const X = '…'` на рекуррентном моменте | `BLOCK_LIFTED_LINE` ×18 за партию (#1422) | главный источник |
| POOL-MAŁY | пул есть, но меньше каденции момента | пул из 3 строк на событие раз в 10 ходов | средняя |
| WINDOW-SKIP | окно повтора не подключено к пути | строка минует `draw`/`line` | bug, как #824 |
| WINDOW-SPLIT | строка в двух колодах: окно каждой слепо к показам другой | COLD_WAR sequential + COLD_WAR_ALL random (#1441) | средняя |
| STATE-STAMP | штамп состояния, повтор задуман | «не доставлено», «добавил в группу» | не дефект сам по себе; считать для контекста |

## Аппарат

Сканер: `src/tools/pool-scan.test.ts`. Прогоны давят партию одним профилем и трассируют
повторы до источников (HARDCODED сам находит файл:строку):

```sh
POOL_SCAN=1 POOL_PROFILES=rude,money,polite POOL_SEED=<новый> POOL_TURNS=160 \
  npx vitest run src/tools/pool-scan.test.ts
# отчёты: /tmp/opencode/pool-scan-<профиль>.md
```

Профили: `rude` (блок-цикл, лестница), `money` (терпение/капитуляции), `polite` (streak), `cow` (мычание/окна), `threat` (суд/вендетта).
Новый профиль добавляется в `PROFILES` — это часть самоулучшения, см. протокол.

## Метод

1. Сид — свежий (не из журналов плейтестов): последний сид журнала ниже + 1000, причём журнал
   читается из воркдерея свежего `origin/main` — локальный чекаут может отставать (урок 4029).
   160 ходов, все профили по очереди.
2. Вердикт по отчёту:
   - **HARDCODED** с показом ≥5 за партию — дефект класса, задача рою (пул + окно);
   - **POOL** с показом > половины размера пула в окне 20 ходов — дефект, проверить окно;
   - **STATE-STAMP** — не дефект, но частота ×20+ — повод для дизайнерской задачи (как #1423);
   - «источник не найден» с высокой частотой — улучшить трассировку (см. протокол), не фейк.
3. Каждая находка — issue task (шаблон Цель/Что происходит/Чего хотим/Не делать/НК) + гист отчёта.

## Протокол самоулучшения (после КАЖДОГО прогона, в том же проходе)

1. **Сканер нашёл то, что нашёл бы человек?** Нет — чинить сканер, не ручную работу:
   примеры: фильтр файлов, съевший все исходники (прогон 1); поиск начала константы вверх
   на 4 строки для многострочных литералов (прогон 1). Фикс — коммитом в тот же PR.
2. **Новый подкласс?** — строка в таксономию. **Ложное срабатывание?** — в исключения.
3. **Журнал прогонов** (ниже) — обязательная строка: дата, сид, профили, находки,
   номера задач, что выучено о сканере.
4. Скил ошибся — правится скил, не обходится (прецедент: `playtest-audit/SKILL.md`).

## Правила, выученные классом

- HARDCODED-константа, вызываемая из `game.ts` на событии с кулдауном — почти всегда
  исчерпание: у константы нет ни пула, ни окна.
- Одноразовая арка (лестница, суд, вендетта) не спасает: цикл под ней переживает арку.
- Строка, доступная из двух колод, незащищена окном каждой из них: sequential-колода не
  видит показов той же строки через random-путь (#1441). Новая колода с пересекающимся
  пулом — всегда кандидат WINDOW-SPLIT.
- Здоровая планка: ≥85% уникальных реплик на профильной партии из 160 ходов; исключение —
  профиль, живущий в режиме с единственным пулом (rude в холодной войне: 53–60% уникальных
  при окне ≤3 — норма режима, сида 2031–5111).
